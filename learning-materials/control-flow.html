条件判断与循环（if / elif / else · for · while）

让程序"会选路、会重复"的两类最基本的语句：用 if 决定这次走哪条分支，用 for / while 把同一件事做很多遍。

生成日期：2026-09-17 · 学习视角：Python 零基础入门（大二 · 第 2 次课） · 资料来源均为公开可核查链接

01学习目标

  • 能用大白话说清 if / elif / else 的执行顺序——从上往下逐个检查，命中一个就跳过其余的。
  • 能说清 for 和 while 各自适合什么场合，并知道 while 在什么情况下会变成"死循环"。
  • 能自己写出"猜数字"小程序的骨架：程序出题 → 循环反复猜 → 用 if 判断是大了、小了还是猜对。

02核心问题

  • Python 判断"真 / 假"到底看什么？为什么 0 和空字符串会被当成"假"？
  • for 和 while 都能重复做一件事，那到底该挑哪个？
  • 循环里的 break 和 continue 差在哪？为什么循环也有 else 这件事特别反直觉？
  • 为什么在 Python 里缩进不是"排版好看"，而是语法的一部分？

03个人解释

我的理解：

学之前我以为条件判断和循环就是两段要背下来的语法格式，敲对了就行。真正写完那个猜数字游戏之后，我的感觉变成了——它们像是给程序装了一个"红绿灯"和一条"传送带"。红绿灯就是 if：程序走到路口，看一眼条件，才知道该往哪边拐。传送带就是循环：同一段动作，把一排东西一件件送上去，重复做，不用我手写十遍。

让我改观最大的一点是缩进。以前写作文式的排版，缩进只是为了好看；但在 Python 里，缩进是"这句话属于哪一块"的唯一标记。我把 print 往前挪了一格、往后挪了一格，结果就完全不一样——这是别的语言里不太有的体验，也让我第一次意识到：代码是写给"解释器"看的，不只是写给人看的。

另外一点是关于 for 和 while 的分工。我一开始老想用 for 硬写"猜到为止"，写得很别扭。后来才想通：for 是"我知道要过一遍哪串东西"，while 是"我知道什么条件下才停"。想清楚这一点，选哪个几乎不用犹豫。

作为大二学生，这是我第一次系统接触编程。这次课最实在的收获不是背会了语法，而是"敢让程序自己重复干活"了。以前遇到要处理一批数据，我下意识想复制粘贴十遍；现在会先想"能不能用一个循环过一遍"。这个习惯正好为后面的课铺路——第 10 次课要做词典法情感打分器，意味着一篇评论的几百个词都要逐个去比对情感词典，手写 if 是不可能的，只能靠循环。所以这两节课学的东西，后面是真的要天天用到的。——杨国美

04核心机制 / 组成

这一节其实只有一个主角："条件"。程序先算出一个能判断真假的值，再根据这个值决定"下一句执行哪里"。

组成部分它做什么什么时候用它
比较与逻辑运算算出一个"真 / 假"的结果。比较用 == != > < >= <=，拼条件用 and / or / not任何需要"判断"的地方，是 if 和 while 的原料
if / elif / else从上往下逐个检查条件，命中一个就执行那一块，并跳过整条判断链的其余部分要在几种情况里选一种，比如"大了 / 小了 / 猜对"
for 循环把一个序列（列表、字符串、range()）里的东西按顺序逐件取出来，取一件做一次你手上有"一串东西"要一件件过一遍
while 循环只要条件还是真，就一直重复做；条件变假就停你不知道要转几圈，只知道"什么情况下才该停"
break / continuebreak 直接跳出整个循环；continue 只跳过本轮剩下的部分，接着做下一轮中途提前收工，或者"这一条不算，跳过"
缩进（4 个空格）标记"哪些语句属于同一块"。它不是排版，是语法每个 if / for / while 后面都得用

执行顺序长这样（文字版流程图）：

if / elif / else 的走法

算第一个条件 → 真就执行这一块并结束 → 假就看下一个 elif → 全假才走 else

while 的走法

检查条件 → 真：执行循环体 → 回到检查条件 → 假：离开循环

注意 while 里必须有一步能让条件最终变假（比如让计数变量加 1），否则会永远转下去，也就是常说的死循环。

一句话记忆法：for 是"我知道要过一遍哪串东西"；while 是"我知道什么条件下才停"。另外，if 的 else 是"前面都不满足"；循环的 else 是"我完整跑完了、没被 break 打断"——两者意思完全不同。

05应用场景（具体例子）

场景一：猜数字小游戏（第 2 次课的下课成品）。

  • 谁用：我自己写、我自己玩，写完要交上去当这次课的作业。
  • 什么环节：程序心里想一个 1 到 100 之间的数，我来猜；每猜一次，它要告诉我"大了"还是"小了"，直到猜中。
  • 程序怎么做（四步）：先用 random 模块的 randint(1, 100) 出题，把答案存进一个变量；然后用 while 开一个循环——因为"要猜几次"事先不知道，只知道"猜中才停"；循环里用 input() 收我猜的数字，再用 if 猜的数 > 答案 / elif 猜的数 < 答案 / else 三路判断；猜对那一支先打印祝贺，再 break 把循环结束掉。
  • 解决了什么：把"要重复问用户直到猜对"这件事交给循环。如果不写循环，就得硬写很多遍 input，而且永远不知道够不够。这里 while 比 for 贴切得多，因为停止条件（猜中）跟"转了多少圈"没关系。

场景二：给后面的情感分析打地基。

  • 什么环节：第 10 次课要做"词典法情感打分器"：给一句话，逐个词去查情感词典，正面词加分、负面词扣分，最后得出这句话偏正面还是负面。
  • 循环在这里做什么：一句话切出来可能有二三十个词，用 for 词 in 词表: 把每个词都过一遍；每过一个词，就用 if 判断"它在正面词典里吗 / 在负面词典里吗"，命中就给总分加上或减去对应的分数。
  • 为什么现在就要练：这正是本次课"AI 关联"埋的那颗种子——写"正面词 / 负面词"的 if 判断，就是情感分析的最小雏形。区别只是：现在我要判断一个词属于哪一类，后面会换成让模型来判断。
  • 一句话的收益：没有循环，处理 100 条评论就得复制 100 遍判断逻辑；有了循环，同一段逻辑套在任意多条数据上都能跑。

06易混淆 / 使用边界

① = 和 == 完全是两件事。= 是"把右边的值存进左边的变量"（赋值），== 才是"判断两边是不是相等"。所以 if x = 1: 会直接报语法错误，正确的写法是 if x == 1:。

② for 和 while 不要硬换着用。要遍历"一串已知的东西"（一个列表、一个字符串、1 到 100）就用 for；"不知道要转几圈、只知道停下来条件"（猜到为止、输入正确为止）才用 while。用 while 去遍历列表很容易忘掉自增，直接变成死循环；用 for 去写"猜到为止"又会很别扭。

③ break 和 continue 是"两档"而不是"一档"。break 是彻底不干了，跳出整个循环；continue 只是"这一条跳过，下一轮继续"。另外，循环的 else 子句只在没有被 break 打断时才执行——它的意思更像 try 的 else（没出错才走），跟 if 的 else（前面都不满足）完全不是一回事。用它正好可以写"我一圈找下来都没找到"这种逻辑。

④ 缩进错了是真会报错的。Python 用缩进表示代码块的归属，缩进不一致会直接抛 IndentationError；混用 Tab 和空格还会抛 TabError。官方 PEP 8 风格指南的建议是：每层统一用 4 个空格，不要用 Tab。这是零基础最容易被恶心到的一处。

⑤ 条件的"真假"规则比想象中宽。数字 0、空字符串 ""、空列表 []、空字典 {}、None 在条件里都算"假"；其他大多数东西都算"真"。所以写 if 用户输入: 时，用户直接敲回车（输入空串）会走 else 那一支——看起来像 bug，其实是这条规则在起作用。

⑥ 别一边遍历一边改那个列表。在 for 循环里对正在遍历的列表做删除操作，容易"漏掉"元素（因为位置在变）。官方教程给的做法是：遍历一个副本，或者干脆另建一个新列表。
