函数与模块（def · import · pip 第三方库）

把一段常用代码"打包"成有名字的功能块，这就是函数；再用 import 把别人写好的功能包拿来用，用 pip 把网上的第三方包装进自己电脑。

生成日期：2026-09-17 · 学习视角：Python 零基础入门（大二 · 第 4 次课） · 资料来源均为公开可核查链接

01学习目标

  • 能说清函数到底解决了什么问题，并会把自己写重复的那段代码改写成 def 函数。
  • 能分清参数和返回值：一个负责"把原料喂进去"，一个负责"把结果交出来"。
  • 会用 import 使用 Python 自带的标准库，会用 pip install 装一个第三方库（jieba）并在代码里真正用上。

02核心问题

  • 为什么说函数不只是"少写几遍代码"？它还带来了什么更重要的好处？
  • pip install 和 import 是两件不同的事，区别到底在哪？
  • 别人写的库凭什么能被我直接拿来用？它被我"装"到电脑的哪个地方去了？
  • 为什么装好了、也写了 import，程序还是报"找不到这个模块"？该往哪儿查？

03个人解释

我的理解：

以前我写代码是"从上往下一路写下来"：要做同样的事，就把那几行复制过来再改改变量名。学完函数之后我觉得，函数就是给一段代码起个名字，然后把它放进工具箱。以后需要它干活，喊一声名字（写一句"函数名(原料)"）就行，不用再把那几行重新抄一遍。更关键的是，起了名字之后，"这段代码是干什么的"变成了一件一眼可读的事——我不用再看它内部的每一行，只要看名字就知道它在干嘛。

关于模块，我的比喻是"别人的工具箱"。像 math、random 这种是 Python 出厂就配好的（叫标准库），不用装，但每次要用还是得先说一句 import，相当于"把工具箱从架子上取下来"。而像 jieba 这种网上别人写好的，就是第三方库——出厂没配，得先去"应用商店"把它买回来，这个商店就是 pip。

最容易混的一点，我一开始也搞错了：我以为 pip install 过之后就可以直接用了。其实不是——pip 是"把它装进我的电脑"（装一次就够），import 是"在这一个 .py 文件里声明我要用它"（每个文件都要写一遍）。装完不 import，程序照样不认识它；反过来，换个新脚本又得重新 import 一次。

作为大二学生，这是我第一次系统接触编程。这次课给我最大的观念冲击是：原来写程序不一定要什么都自己写。做中文文本分析时，老师直接让我们用 jieba 来切词——如果自己从零写一个中文分词算法，别说一节课，一个月都写不出来。我一开始还有点"用别人的算不算作弊"的别扭，后来想通了：真正的能力是知道"这件事有现成的轮子"、知道怎么把它装好、怎么接进自己的代码里。这也让我对后面要学的 sklearn、大模型 API 没那么害怕了——它们本质上都是"别人的工具箱"而已，我要练的是"会用工具箱"这件事。——杨国美

04核心机制 / 组成

这一节其实就三个新面孔：def、import、pip。它们分工非常清楚。

名词白话解释例子
函数 def给一段代码起个名字，包起来。以后喊名字就能让它干活def word_count(text): ...
参数调用函数时"喂进去的原料"。写在括号里，函数内部拿它当普通变量用word_count(我的文章) 里的"我的文章"
返回值 return函数算完之后"交还给你"的结果。没写 return 的函数返回 Nonereturn len(words)
模块 module一个装着功能和定义的 .py 文件；别人打包好的一堆功能也算math、random、jieba
import"这个文件里我要用某个模块"，先声明，再使用import jieba 之后才能写 jieba.lcut(...)
pipPython 的"应用商店"，负责把网上的第三方包装进本机pip install jieba

关键点一：定义 ≠ 调用，这是两件事。写 def greet(name): ... 只是"把工具做好并贴上标签"，程序跑到这里并不会执行里面的内容。要它真干活，必须再单独写一行 greet('杨国美')，这叫调用。零基础最常见的"我明明写好了，怎么什么都没输出"，十有八九就是忘了调用。

关键点二：要把结果带出去，必须用 return。函数里写 print 只是"打印给人看"，结果还留在函数内部，外面拿不到。想在外面接着用这个结果，就得 return 出来。如果一个函数压根没写 return，它返回的是 None——这和上一份资料里 list.sort() 返回 None 是同一回事：有些操作只干活、不交结果。

关键点三：import 有三种常见写法，各有各的场合。

  • import 模块名 → 之后写 模块名.功能名()。最推荐、最不容易撞名字，能一眼看出这个功能来自哪里。
  • from 模块名 import 功能名 → 之后直接写功能名。省事，但代价是看不出它来自哪个模块。
  • import 模块名 as 别名 → 起个短名字，比如 import numpy as np。这是业界通行写法，看到 np 就知道是 numpy。

关键点四：装一个第三方库，记住"两次"。

  1. 装一次（在终端里，不是在你写的 .py 里）：执行 pip install jieba。这一步是让电脑把这个包下载好、放到 Python 能找到的地方。
  2. 每次用都要 import（写在自己的 .py 文件开头）：写 import jieba，然后用 jieba.lcut('我爱自然语言处理') 这样的方式调用它的功能。

pip 默认从 PyPI（Python Package Index，可以理解成 Python 的官方应用商店）下载。装完之后，这个包会被放到 Python 安装目录下的 site-packages 里，import 的时候解释器就是去那里找的。

从"想要一个功能"到"用上它"（文字版）

pip install jieba（装进电脑） → import jieba（在 .py 里声明） → jieba.lcut(text)（真正调用）

一句话记忆法：pip 是"买回来放进工具箱"，import 是"把工具箱搬到这张桌子上"，调用是"拿出工具开始干活"。三步缺一不可。

05应用场景（具体例子）

场景：用 jieba 做一个中文文本分析小工具（第 4 次课的下课成品）。

  • 谁用：我自己；交上去的验收标准是"丢进一段中文，能打印总词数和词频前 10"。
  • 什么环节：前两次课我能统计英文词频了，但换成中文就卡住——英文有空格，中文没有。程序面对"我爱自然语言处理"这 8 个字符，根本不知道该从哪儿断开。切词这件事，正是要用别人的轮子。
  • 怎么搭起来（三块积木）：
    1. 先用 pip 装：在终端里跑 pip install jieba。选它是因为它是纯 Python 写的，安装不会卡在"编译失败"这种让零基础最崩溃的地方。
    2. 再用 import 用：文件开头写 import jieba，然后用 jieba.lcut(我的中文) 得到一串词——它返回的正好是一个列表，比如 ['我', '爱', '自然语言', '处理']。
    3. 最后自己写一个函数把它固定下来：定义 def word_count(text):，函数体里做三件事——用 jieba 切词并过滤掉长度只有 1 的字（因为"的、了、在"这类单字噪音大）、用字典统计每个词的次数、返回总词数和排好序的前 10 条。之后要看新的一段文本，只要 word_count(新文本) 就行，函数体一行都不用改。
  • 解决了什么：把"一件专业且困难的事"（中文分词）交给成熟的库，把"自己这段会反复用到的逻辑"（统计 + 排序）固化成函数。这样换一段文本、换一个场景（比如换成情感分析的一段评论），复用的成本几乎为零。
  • 顺手学会的读报错技能：如果忘了装，会看到 ModuleNotFoundError: No module named 'jieba'。这句话直译就是"我找不到名叫 jieba 的模块"——要么没装，要么装到了另一个 Python 环境里。第 4 次课的一个重要目标就是"读懂报错并改代码"，而不是一看到红字就慌。

06易混淆 / 使用边界

① 定义 ≠ 调用。写 def 只是"把工具做出来"，不会自动运行；必须有另一行去调用它。这是"代码写了但没输出"最常见的原因。

② 参数 ≠ 返回值。参数是进门时喂进去的原料，返回值是出门时交出来的结果。要在函数外面拿到结果，必须 return；只在函数里 print 是不够的——外面拿到的是 None。

③ pip install ≠ import。install 是"装进电脑"（一台电脑装一次，装在终端里执行）；import 是"在这个 .py 文件里声明要用它"（每个文件都要写）。装好了不 import，还是用不了。

④ 装好了却 import 失败，多半是"两个 Python"。电脑上如果有多个 Python 版本，或者开了虚拟环境，很容易出现"pip 把包装到了 A 环境，但我是用 B 环境的 Python 跑的"。这时改用 python -m pip install jieba 更保险——它的意思是"就用当前这个 python 去执行 pip"，能保证装到同一个地方。

⑤ 别写 from 模块 import *。它会把这个模块里一大批名字全都倒进当前文件，可能覆盖掉你自己定义的同名东西，出错之后非常难查。官方文档也明确不建议这么写。用什么就写什么：import jieba 然后 jieba.lcut(...)，或者 from jieba import lcut。

⑥ 函数也不是越多越好。只为"少写两行"而把一段只用一次的逻辑硬抽成一个函数，反而让人多跳一次才能看懂。值得抽成函数的情况是：这段逻辑会被反复用到，或者单独给它起个名字之后代码明显更好读。

⑦ 边界：函数内部的变量是"局部的"。在函数里给一个变量赋值，不会影响函数外面同名的变量；函数结束后，它内部的变量也就消失了。这是设计上的保护（避免互相干扰），但也常让人困惑"我在函数里明明改了，外面怎么没变"。
