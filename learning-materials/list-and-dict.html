列表与字典（list 与 dict）

Python 里最常用的两个"容器"：列表 按顺序装一串东西，靠"第几个"去取；字典 装"名字 → 内容"的对应关系，靠"叫什么"直接找到。

生成日期：2026-09-17 · 学习视角：Python 零基础入门（大二 · 第 3 次课） · 资料来源均为公开可核查链接

01学习目标

  • 能用一句话说清 列表（list） 和 字典（dict） 的差别，并在写代码时选对容器。
  • 会做列表的增、删、改、查、切片和遍历；会用 sorted() 把结果排好序，取出"出现次数最多的前 5 个"。
  • 会创建字典、按键取值、遍历键值对，并说清为什么"词频统计"这件事几乎总用字典来做。

02核心问题

  • 列表按"第几个"取，字典按"叫什么"取——这个差别落到写代码时，到底意味着什么？
  • 同一个词在文章里出现 100 次，如果用列表记要怎么写？用字典又要怎么写？谁更省事？
  • 为什么给字典排序时必须写 key= 才能按"次数"排？默认排序排的是什么？
  • d['键'] 和 d.get('键') 有什么区别？遇到不存在的键分别会怎样？

03个人解释

我的理解：

学之前我觉得"装东西的容器"不就一种吗，够用就行。学完之后我给它们各配了一个画面：列表像一支排好的队伍——你喊"第 3 个出列"，出来的就是第 3 个，谁在第几号位置是固定的，插队和离队都会让后面的人挪位置。字典像一本通讯录——你不关心"老王翻到了第几页"，只关心"老王是谁"，报上名字就把电话给你，哪怕这本通讯录有 700 条记录，找起来也是"一步到位"。

真正让我"啊哈"一下的是做词频统计的时候。一开始我想用列表存：遇到一个词就把它 append 进去，最后再数有多少个重复的——写起来又长又慢。换成字典之后，整个逻辑短得不像话：把"词"当名字用，把"次数"当内容存，遍历一遍文章，遇到一个词就把它的计数加 1。counts.get(词, 0) + 1 这一句话里其实藏着一句大白话："这个词之前数过吗？没数过就当 0，然后加 1 存回去。"

还有一点是我以前完全没意识到的：这个"手工词频统计"，其实就是后面要学的 词袋模型（Bag of Words） 的手写版。老师讲的时候说"你们第 3 次课已经自己实现过一遍了，只是第 5 次课换成库函数"，我当时还挺意外的——原来这些看起来最土的循环和字典，就是 AI 处理文字的地基。

作为大二学生，这是我第一次系统接触编程。这次课对我最大的改变是"先想数据长什么样，再想代码怎么写"。以前拿到任务就急着敲循环，现在会先问自己一句：这些东西有顺序吗？我是要"按第几个取"还是"按名字取"？想清楚这一点，剩下的代码往往就顺下来了。更有意思的是，我发现"用字典记次数"这个套路，在后面的情感分析里还会再见一次——那时候字典的键是情感词、值是分数。所以现在多练几遍，后面就少卡几次。——杨国美

04核心机制 / 组成

两个容器解决的是两种不同的"找东西"需求：

容器怎么取东西适合装什么常用操作
列表 list
[a, b, c]		 用位置（下标）：
a[0] 第一个，a[-1] 最后一个，a[1:3] 切片		 有先后顺序的一串东西：一篇文章切出来的所有词、一批分数、一个待办清单 append 加、remove/pop 删、sort 就地排序、len 数长度、for 遍历
字典 dict
{键: 值}		 用键（名字）：
d['apple']，取不到会报错；
d.get('apple', 0) 取不到给默认值		 成对的"名字 → 内容"：词 → 出现次数、学号 → 姓名、情感词 → 分数 d[键] = 值 存、d.get 安全取、d.items() 同时遍历键和值、in 判断键在不在

关键点一：下标从 0 开始，切片"含头不含尾"。举例：words = ['a', 'b', 'c', 'd']，那么 words[0] 是 'a'，words[1:3] 是 ['b', 'c']——取到了 1 号位置，但取不到 3 号位置。刚开始最容易在这里少取或多取一个。

关键点二：有些列表方法"改的是自己，不给你返回值"。像 append、sort 这类方法都是直接改原来的列表，它们自己返回的是 None（也就是"没有值"）。所以 nums = nums.sort() 会让 nums 变成 None；想要一个排好序的新列表，应该用 sorted(nums)。

关键点三：词频统计的标准三步走。

  1. 把文章变成一串词：对英文可以先 text.lower().split()（转小写再按空格切开），得到一个列表。
  2. 用字典记次数：准备一个空字典 counts = {}，然后 for 遍历每个词，执行 counts[词] = counts.get(词, 0) + 1。get(词, 0) 的意思是"字典里没有这个词就当成 0"，所以第一次遇到它会存成 1，之后再遇到就 2、3、4……
  3. 排序取前几名：sorted(counts.items(), key=lambda kv: kv[1], reverse=True)[:5]。counts.items() 把字典变成一串 (词, 次数) 的记录；key=lambda kv: kv[1] 是告诉排序"按每条第 2 项（也就是次数）来比"（这里 lambda 可以理解成"临时现写的一个小规则"，看不懂先照着抄也行）；reverse=True 表示从大到小；[:5] 取前 5 条。

词频统计的数据流（文字版）

一篇文章 → 一个词列表 list → 一个词频字典 dict → 排好序的前 5 条

另外，第 3 次课还会遇到一个"简化写法"叫列表推导式：[w for w in words if len(w) > 3]，白话就是"把 words 里长度超过 3 的词挑出来，组成一个新列表"。它等价于写了三行 for + if，看起来更紧凑；一开始不熟的话，先用普通 for 循环写完全没问题。

05应用场景（具体例子）

场景一：英文文章词频统计（第 3 次课的下课成品）。

  • 谁用：我自己写的小脚本，用来喂任何一篇英文文章。
  • 什么环节：手上有一篇大约 2000 个词的英文文章，我要快速看出"它主要在讲什么"——最直接的办法就是看哪些词出现得最多。
  • 具体怎么做：把文章读进来 → lower() 统一成小写（避免 The 和 the 被算成两个词）→ split() 切出一个约 2000 项的词列表 list → 用一个空字典 counts 遍历计数，这一步之后字典里大概会有 700 个键（因为去重了，2000 个词里很多是重复的）→ 最后 sorted(...)[:5] 打印出现最多的前 5 个词。
  • 解决了什么：2000 个词如果存成列表，我"知道所有词"，但根本没法回答"哪个词最多"；换成字典之后，"词 → 次数"变成了一个查得到的东西，我直接按值排个序就出结果了。这正是"选对容器"带来的差别。
  • 踩过的坑：一开始写成 counts = counts.get(词, 0) + 1，把整个字典换成了一个数字；正确写法是 counts[词] = counts.get(词, 0) + 1——左边那一段不能省掉，它是"存回去"这个动作。

场景二：为后面的情感分析做准备。

  • 后面要做什么：第 10 次课的"词典法情感打分器"：给一句中文，逐个词查情感词典，正面词加分、负面词扣分，最后判断整句偏正面还是负面。
  • 这两个容器怎么分工：情感词典本身就是一个 dict——键是情感词、值是分数，比如"满意"记 +1、"糟糕"记 -1，这样查一个词是不是情感词只要一步；而一句话切出来的所有词是一个 list，用 for 逐个过一遍，每过一个就从词典里取一次分数、累加到总分上。
  • 还有一个真实的小细节：中文没有空格，所以"切词"这一步要交给后面的第三方库（jieba）。但切完之后，"把词装进列表、把分数装进字典"这套动作，跟今天做的词频统计是一模一样的。今天练的，就是那一步的地基。

06易混淆 / 使用边界

① 方括号是列表，花括号是字典。[1, 2, 3] 是列表，{'a': 1} 是字典。[] 是空列表，{} 是空字典——注意 {} 不是空集合，空集合得写 set()。这个小细节特别容易记反。

② 下标从 0 开始，切片含头不含尾。words[0] 是第一个元素，words[-1] 是最后一个；words[1:3] 只取到第 2、第 3 个元素，取不到第 4 个。另外，下标超出范围（比如 4 个元素却取 words[10]）会直接抛 IndexError。

③ 有些列表方法返回的是 None，别接返回值。append、sort、reverse 都是"就地修改"，自身不返回值。写 nums = nums.sort() 会把 nums 变成 None；正确做法要么只写 nums.sort()，要么写 nums = sorted(nums)（sorted() 才是"给你一个新的排好序的列表"）。这也是零基础最常见的 bug 之一。

④ d['键'] 和 d.get('键') 不是一回事。用中括号取一个不存在的键会直接抛 KeyError，程序当场停下；get() 则返回 None，也可以写成 get('键', 0) 指定默认值。做统计时先用 get，代码更不容易崩。

⑤ 字典的键必须是"不可变"的。字符串、数字、元组可以当键；列表不能当键（因为列表可以被改来改去）。另外，字典的键是唯一的——用同一个键存两次，后一次的会覆盖前一次。

⑥ 排序时要分清"排谁"和"按什么排"。给字典排序，实际是在给 d.items() 产生的"键值对序列"排序，所以要写 key= 告诉它按值（kv[1]）还是按键（kv[0]）来比。不写 key= 时，它会按整个键值对去比，结果通常不是你想要的那个顺序。

⑦ 使用边界：字典擅长"按键找值"，不擅长"按位置取"。虽然从 Python 3.7 起字典会记住插入顺序，但它的设计目标是"给你一个名字、换回一个内容"，不要把它当成"第 3 个是什么"的容器用——要按顺序取，就该用列表。
