Python 运算符

运算符是 Python 里的「动词」——变量负责装东西，运算符负责对东西做事，并且常常吐出一个 True / False 交给下一步去判断。

生成日期：2026-09-24 · 学习视角：Python 零基础入门（第 1–2 次课之间的补充卡） · 资料来源均为公开可核查链接

01学习目标

  • 能说清 / 和 //、% 三者的分工，并知道 10 / 2 为什么得到的是 5.0 而不是 5。
  • 能读懂 0 or "默认值" 这类写法，并说出 and / or 返回的为什么不是 True / False，而是其中一个操作数。
  • 能写出一个用 +=、in、and、or 给文本打分的六七行小脚本，并知道为什么判断两个小数是否相等不能用 ==。

02核心问题

  • 已经有了 /，Python 为什么还要专门做一个 //？它和 % 之间有什么关系？
  • 1 < x < 10 在 Python 里能得到正确结果，在 C 语言里却是一个「永远为真」的经典 Bug。同样是这行字，差别在哪？
  • 0.1 + 0.2 == 0.3 为什么是 False？那要判断两个小数「相等」，该怎么办？
  • 5 and 3 得到 3，0 or "匿名" 得到 "匿名"——逻辑运算符凭什么不老实回答「真 / 假」？

03个人解释

我的理解：

我一开始以为运算符就是小学数学那套：加、减、乘、除，没什么可学的。结果第一个就翻车了——我写 10 / 2，本以为得到 5，屏幕上却是 5.0。查了才知道：Python 里的 / 是「真除法」，结果永远带小数点；想要「整除」，得用两个斜杠 //。更让我意外的是 -7 // 2 得到的是 -4 而不是 -3——它不是「把小数部分砍掉」，而是「往下取，取到更小的那个整数」。这两个词看着像一回事，对负数来说完全是两回事。

真正颠覆我认知的是 and 和 or。我一直以为它们只会回答「是 / 否」，直到看见 0 or "匿名" 这一行——它竟然返回了字符串 "匿名"！原来 or 的规则是「左边能当真的话就把左边还给你，否则把右边还给你」，返回的是操作数本身，不是布尔值。想通这一点之后，我忽然明白为什么别人写程序时能用一句 name = input("名字：") or "匿名" 来做「没填就用默认值」——它根本不是逻辑判断，而是一个懒人版的选择器。and 也是同理，只是方向反过来。

第三个让我后背发凉的是浮点数比较。我随手写 print(0.1 + 0.2 == 0.3)，得到的居然是 False。原因不是 Python 坏了，而是 0.1 这类小数在电脑里本来就存不准（二进制表示不完美，就像 1/3 在十进制里也写不完）。所以判断两个小数「相等」不能直接用 ==，得看它们是不是「足够接近」，用 math.isclose() 或者 abs(a - b) < 1e-9。

作为 Python 零基础的大二学生，学完这一节我最大的感受是：运算符不只是算数，它是「判断」的原料。>、in、== 这些写出来都会得到 True / False，而下一节课的 if 要吃的正是这个东西——运算符负责问问题，if 负责按答案走路。另外我也记住了一条自我保护的规矩：优先级拿不准就加括号，代码是给人读的，少省两个括号换不来任何好处。——杨国美

04核心机制 / 组成

Python 的运算符按「它负责干什么」分成六类。下面每类都先给表，再挑最容易踩的地方单独讲。

机制一：算术运算符 —— 两个除法，一个取余

运算符名称例子结果
+加7 + 29
-减7 - 25
*乘7 * 214
/真除法（永远带小数）10 / 25.0
//整除（向下取整）7 // 23
%取余（余数）7 % 21
**幂（几次方）2 ** 101024

关键一：/ 的结果一定是 float。哪怕除得干干净净，10 / 2 也是 5.0 而不是 5 [来源 1]。这在后面算准确率时很关键——正确数 / 总数 自然就是小数，不需要额外转换。

关键二：// 叫「向下取整」，不叫「砍掉小数」。对正数两者结果一样，对负数就分道扬镳 [来源 2]：

7 // 2   # → 3    （向下取，得 3）
-7 // 2  # → -4   （不是 -3！-3.5 往下取到 -4）

关键三：// 和 % 是一对。它们满足一个恒等式，记住它这两个运算符就再也不会记混 [来源 2]：

a == (a // b) * b + a % b    # 商 × 除数 + 余数 = 原来的数

拿 7 和 2 验一下：7 // 2 = 3，3 * 2 + 1 = 7 ✓。所以取余 % 的符号是跟着除数走的：-7 % 3 得到 2（不是 -1）。日常用 % 判断奇偶（x % 2 == 0）不受影响，因为那时除数总是正数。

机制二：比较运算符 —— 产出「真 / 假」

运算符含义例子结果
==是否相等3 == 3.0True（数值相等即可，类型可以不同）
!=是否不相等"a" != "b"True
> <大于 / 小于5 > 3True
>= <=大于等于 / 小于等于5 >= 5True

特点一：比较的结果是 bool。这正是 if 语句要的东西——if 后面跟一个能得出 True / False 的表达式，它就决定走哪条路。所以「运算符」和「条件判断」是同一件事的两半。

特点二：Python 支持「链式比较」。数学里写惯了 1 < x < 10，Python 直接照抄就能用，它等价于 1 < x and x < 10 [来源 5]：

x = 5
1 < x < 10       # → True  等价于 (1 < x) and (x < 10)
1 < 5 < 3        # → False （5 < 3 不成立）

在 C / Java 里，1 < x < 10 会被理解成 (1 < x) < 10，也就是 True < 10，恒为真——这是经典的踩坑写法。Python 特意把它做成了符合数学直觉的样子。

特点三：字符串也能比大小，规则是「按字符逐个比 Unicode 码点」，所以 "apple" < "banana" 是 True（a 在 b 前面）。但字符串和数字之间不能比大小，"3" > 2 会直接抛 TypeError——Python 3 不许你这么干，逼你把类型转对再比。

特点四：浮点数不能用 == 比。这是本卡最重要的一条实用规则 [来源 3]：

0.1 + 0.2          # → 0.30000000000000004  （不是 0.3）
0.1 + 0.2 == 0.3   # → False

import math
math.isclose(0.1 + 0.2, 0.3)  # → True  √ 正确写法

机制三：逻辑运算符 —— 短路求值 + 返回操作数

写法规则例子结果
a and ba 为假 → 返回 a；否则返回 b5 and 33
a and b同上0 and 30
a or ba 为真 → 返回 a；否则返回 b5 or 35
a or b同上0 or "默认""默认"
not a把它变成真 / 假not 0True

第一个特点：返回的是操作数，不是布尔值。只有 not 才保证返回 True / False。and / or 返回的是参与运算的那一方本身。所以 5 and 3 得到 3，这看着奇怪，但带来了两个非常好用的写法：

name = input("你的名字：") or "匿名同学"  # 没填（空字符串算“假”）就用默认值
greeting = name and f"你好，{name}"     # name 为空时，整句直接为空，不打印废话

哪些东西算「假」？记住这几个就够：False、0、0.0、""（空字符串）、[]（空列表）、{}（空字典）、None。除此之外基本都算「真」。这个清单在文本分析里很有用——「这句话有没有命中任何关键词」，看列表是不是空的就行。

第二个特点：短路求值。and 一发现左边是假，就不再算右边；or 一发现左边是真，也不再看右边。这能顺手挡掉错误：

if x != 0 and 10 / x > 2:    # x 为 0 时，and 左边已假，10/x 根本不会执行

如果把顺序反过来写成 10 / x > 2 and x != 0，x 为 0 时就会先撞上「除零错误」。顺序不是小事。

机制四：赋值运算符 —— 简写法

+= 这类是「先算右边，再存回左边」，本质就是一句缩写，没有任何魔法 [来源 1]：

简写完全等价于典型场景
count += 1count = count + 1计数器：又数到一个
score -= 2score = score - 2情感打分：这个词是负面的
total *= 2total = total * 2成倍增长
n //= 2n = n // 2每次折半取整

写 count += 1 比 count = count + 1 更少出错（少写一遍变量名，就少一次拼错的机会）。注意不能写成 count++——那是 C / Java 的写法，Python 里没有。

机制五：成员运算符与身份运算符

运算符问的问题例子结果
in这东西在里面吗？"免费" in "免费领取"True
not in这东西不在里面吗？"猫" not in "今天下雨"True
is是不是同一个对象？x is None判断「有没有值」的正规写法
is not是不是不同的对象？x is not None判断「有值」

in 是文本分析里出现频率最高的运算符之一：「这个词在不在停用词表里」「这句短信有没有出现敏感词」，全靠它。

is 和 == 只在一件事上分工明确：跟 None 比较一律用 is。None 在 Python 里全局只有一个，所以 x is None 既准确又比 x == None 快。至于「小整数缓存」（-5 到 256 的整数是共用的，出了这个范围 is 的结果就不一定了）——知道有这回事就行，平时一律用 == 比值，别用 is。

机制六：优先级 —— 谁先算

从高到低，只需要记这七档 [来源 1]：

1. ()               括号最优先
2. **              幂
3. -x（正负号）    取负
4. * / // %       乘除类
5. + -             加减类
6. == != > < >= <= in is  比较类
7. not → and → or  逻辑类（最后算）
2 + 3 * 4      # → 14  （不是 20，乘法先算）
-2 ** 2         # → -4  （幂先于取负，等于 -(2**2)）
not 1 + 1 == 2  # → False（先算 1+1，再比 ==2，最后才 not）

最实用的一条：不确定就加括号。括号不但不会错，还会让别人（和三个月后的自己）一眼看懂你的意思。为了省一对括号去背优先级表，是笔亏本买卖。

05应用场景（具体例子）

把这一节学的运算符全用上，写一个「短信风险打分器」——它就是第 8 次课「垃圾短信识别」的手工版雏形：给一条短信打分，分数够了就提示拦截。

text = input("请粘贴一条短信：")

score = 0
score += 2 if ("免费" in text or "中奖" in text) else 0
score += 2 if ("点击" in text and "链接" in text) else 0
score += 1 if ("！" in text or "!" in text) else 0
score += 1 if len(text) > 50 else 0

print(f"风险分：{score} / 6")
print("建议：拦截" if score >= 4 else "建议：放行")
  • 用到的算术运算符：+= 累加分值（等价于 score = score + 2）。
  • 用到的比较运算符：> 判断短信长度、>= 判断分数够不够。它们各自产出一个 True / False。
  • 用到的逻辑运算符：or 表示「命中任一个就加分」，and 表示「两个都出现才加分」——这两种严格程度要分开，and 更严，误报更少。
  • 用到的成员运算符：in 判断关键词有没有出现。
  • 用到的语法：A if 条件 else B 是 Python 的「一行版 if」，本卡只借它来少写几行，正式讲它是在下一张卡。

试试看：把第一个条件里的 or 换成 and，拿「免费领取优惠券，点击链接查看详情！！」再跑一次——分数会从 5 掉到 3，因为它只命中了「免费」，没命中「中奖」。and 更严格，误拦更少，但也更容易漏掉该拦的短信；or 更宽松，抓得全，但容易误伤正常短信。这个岔路口就是第 9 次课要讲的「精确率」和「召回率」在争的东西。

06易混淆 / 使用边界

容易混淆的点说清楚
= / == / is三个层次：= 是赋值（把名字贴到数据上，不产生结果）；== 比值是否相同；is 比是不是同一个对象。a = [1,2] 与 b = [1,2] 时，a == b 是 True，a is b 是 False [来源 5]
/ 与 //10 / 2 → 5.0（float）；10 // 2 → 5（int）。要「整除的整数结果」就用 //，想省这一步转换会踩坑
// 的方向是「向下取整」不是「向零取整」：-7 // 2 → -4。对正数感觉不出来，对负数就是错一格
% 的符号余数的符号跟着除数走：-7 % 3 → 2；7 % -3 → -2。判断奇偶（x % 2 == 0）时不受影响
用 == 比浮点数0.1 + 0.2 == 0.3 是 False。这是二进制存小数的固有误差，不是 Python 的毛病。改用 math.isclose(a, b) 或 abs(a - b) < 1e-9 [来源 3][来源 4]
and / or 的返回值返回的不是 True / False，而是其中一个操作数：5 and 3 → 3，0 or "默认" → "默认"。放进 if 里当条件用当然没问题，但直接 print 出来时会看到「意料之外」的东西
not 与 !=not a == b 是「a 不等于 b」的意思（先算 ==，再 not），而 a != b 是同一个意思的正规写法。写后者，前者容易看错
字符串 vs 数字"3" > 2 抛 TypeError；"3" + 4 也抛 TypeError。字符串之间比大小是按码点逐字比，"10" < "9" 是 True（先比首字符 '1' 与 '9'），和数字直觉完全不同
++ 与 --Python 里没有自增自减运算符。写 count++ 会报语法错误，正确的是 count += 1
依赖优先级-2 ** 2 → -4（先幂后取负），2 ** 3 ** 2 → 512（幂是右结合的，等于 2 ** 9）。这类地方一律加括号，别赌自己的记忆力

什么时候「不该用」运算符解决问题？当你需要比较三个以上条件、或判断条件本身很复杂时（比如「是会员 且 消费满 100 且 不是退货单」），硬写一个长表达式会让 if 越写越读不懂。那时应该拆成几个有名字的中间变量，让每一行只回答一个问题——可读性比少写两行重要得多。
