文本的数字化（分词 · 词袋模型 Bag of Words · TF-IDF）

计算机只认数字，不认文字；把一段文本切碎、编号、计数、加权，变成一串数字的过程，就叫“文本向量化”。

生成日期：2026-09-17 · 学习视角：AI 初学者 · 从“文字怎么变成数字”入门自然语言处理 · 资料来源均为公开可核查链接

01学习目标

  • 能说清“文本数字化”的完整链路：分词 → 建词表 → 计数/加权 → 得到向量，每一步在干什么。
  • 能用自己的话解释词袋模型为什么“只看有哪些词、各几个，不看顺序”，以及这么做的代价是什么。
  • 能说明 TF-IDF 在词袋基础上多做了什么、它想解决什么问题，并在什么情况下会失效。

02核心问题

  • 为什么机器不能直接“读”中文句子，非要先把它变成一串数字？
  • 词袋模型把语序全扔掉了，为什么在很多任务上它还是够用、甚至比复杂模型更稳？
  • TF-IDF 凭什么认为“到处都是的词就不重要”？这个假设什么时候会翻车？

03个人解释

我的理解：

我一开始以为“让 AI 读懂文字”应该是很玄的事，学完这节才发现，第一步朴素得有点可爱：先把句子切成一堆词，再数数每个词出现了几次，排成一排数字交出去。这排数字就是“向量”，机器拿到它才终于能开始算。

我最喜欢的一个比喻是词袋模型 = 把句子里的词倒进一个袋子：只看袋子里有哪些词、各几个，完全不管谁先谁后。“我打你”和“你打我”倒进同一个袋子，得到的结果一模一样——这既说明了它简单、稳、快，也说明了它最大的毛病：它不知道词序，也不知道词之间的关系。

而 TF-IDF 是在这个基础上加了一层“打分”。它的直觉我觉得特别好懂：一个词如果在我这篇文章里反复出现，说明它对我重要（TF）；但如果它在所有文章里都到处出现，那它对区分文章就没什么用（IDF 把它压下去）。所以“的、了、是”这种词权重被压到很低，“考研、实习、绩点”这种词权重被抬高——它其实是在自动帮我找出“这篇到底在讲什么”的关键词。

作为大二学生，这是我第一次系统接触自然语言处理。最大的冲击是：我原以为“理解语言”是很智能的事，结果文本数字化的第一代方法朴素到只是“切词 + 数数”。但更让我意外的是，这种朴素方法到今天还在被大量使用——因为它快、便宜、结果可解释（我能直接看到哪个词权重最高）。学完这节我才真正理解：模型聪明不聪明是一回事，能不能把原始数据翻译成模型看得懂的形式，往往是更前置、更关键的一步。以后我做课程项目处理文本时，会先老老实实跑一遍 TF-IDF 当作基线，而不是一上来就上大模型。——杨国美

04核心机制 / 组成

把一句话变成向量，工程上是四步流水线（scikit-learn 把后三步打包在 CountVectorizer / TfidfVectorizer 里）[来源 1][来源 2][来源 3]：

步骤它在做什么通俗理解
① 分词 Tokenization把整段文本切成一个个“词 / 词元”把句子拆成一块块小积木
② 建词表 Vocabulary统计语料里出现过的所有不同词，给每个词编一个号造一本“词 → 第几号”的字典
③ 词袋计数 Bag of Words对每篇文档，数每个词出现了几次，按词表顺序排成一排数字把袋子里的词倒出来点数
④ TF-IDF 加权把“次数”换成“权重”，到处都是的词降权，只有这篇有的词升权给每个词打一个“代表性分数”

分词这一步，中文比英文麻烦。英文天生有空格，“Machine learning is fun” 直接按空格切就行；中文写起来没有空格，“我爱学习自然语言处理”到底切成“自然语言 / 处理”还是“自然 / 语言 / 处理”，需要专门的算法。常用做法有两类：

  • 规则 + 统计：如 jieba（结巴分词），用前缀词典扫出所有可能的切分，再用动态规划找”概率最大“的那条路径，未登录词用 HMM 模型兜底 [来源 5]。
  • 工业级 NLP 库：如 spaCy，按语言的规则处理缩写、标点、前后缀，中文还会单独处理（如 BERT 的分词器会给中文加空格）[来源 6]。

词袋模型（Bag of Words）的核心假设只有一句：一篇文档的意思，由它包含哪些词、各出现多少次决定，与词的排列顺序无关。所以它有两个直接后果：

  • 优点：实现极简、训练极快、结果可解释（能直接看到哪几个词贡献最大），并且词表维度就是特征维度，不需要神经网络 [来源 2]。
  • 缺点：语序、否定、搭配信息全丢；向量维度 = 词表大小（动辄几万维），而且每篇文档里绝大多数位置都是 0，属于典型的高维稀疏数据 [来源 1]。

TF-IDF（词频 × 逆文档频率）是在词袋计数上做的加权修正，它解决的是”长文档天然计数更高“和”高频虚词噪声太大“这两个问题 [来源 1][来源 3]：

  • TF（Term Frequency，词频）：某个词在这篇文档里出现的频率。可以简单理解为”出现越多越重要“。在 scikit-learn 的默认设置里，TF 就是原始计数 [来源 3]。
  • IDF（Inverse Document Frequency，逆文档频率）：一个词的信息量指标——它在越多文档里出现，IDF 越低（越不稀奇，越不能用来区分文档）；只在少数文档里出现，IDF 越高。
  • TF-IDF = TF × IDF：两者相乘。结果就是——“在我这篇里很突出、但在别人那很少见”的词，得到最高权重。

文本 → 向量的完整链路

“我 喜欢 考研 数学” → [分词] → 我 / 喜欢 / 考研 / 数学 → [查词表编号] → 12, 37, 88, 204 → [计数/TF-IDF 加权] → (0, 0.51, 0.82, 0.71, 0, …0) → 一个 3 万维的稀疏向量

最后，两篇文档像不像，就用这两个向量的余弦相似度来算：看它们在多维空间里”指向的方向“有多接近（0 表示完全无关，1 表示方向完全一致）[来源 4]。

一句话记忆法：词袋 = 切词 + 数数；TF-IDF = 数数之后，把“全科都有的词”降价、把“只有我会的词”提价。

05应用场景（具体例子）

场景：给学院公众号做”文章自动分类 + 相似文章推荐“。

  • 谁用：负责运营学院公众号的大二学生（就是我），手上攒了 150 多篇历史推文。
  • 什么环节：每篇推文发出去之前要手动选标签（保研 / 实习 / 社团活动 / 竞赛），还要在文末挂 3 篇”相关阅读“。手选 150 篇，一晚上就没了。
  • 怎么用这套方法做：① 用 jieba 对标题+正文分词，去掉”的 / 了 / 我们 / 学院“这类停用词 [来源 5]；② 用 TfidfVectorizer 把每篇变成 TF-IDF 向量 [来源 3]；③ 用逻辑回归（scikit-learn 里的 MultinomialNB 之类同理）学一个”向量 → 标签“的分类器 [来源 1]；④ 用 cosine_similarity 算每篇文章两两之间的相似度，取 Top 3 当”相关阅读“ [来源 4]。
  • 解决了什么：分类从”一晚上“变成”跑一遍脚本“；而且结果可解释——我能把某个标签下权重最高的词打印出来，看到”原来模型是看到 '推免 / 绩点 / 夏令营' 才判成保研类的“，出错了也能定位原因。
  • 暴露的局限：有篇讲”面试经验“的文章被推荐给了”笔试攻略“——因为字面上一个词都不重叠。同义不同词，是词袋模型天生的盲区，这也正是后面要学的”词嵌入 / 词向量“想解决的问题。

06易混淆 / 使用边界

① 词袋/TF-IDF 向量 ≠ 词向量（Word Embedding）。这是最容易混的一对。TF-IDF 向量是”数出来的“，维度等于词表大小（几万维），绝大多数是 0，而且”考研“和”保研“是两个完全垂直、毫不相干的方向；词嵌入是”学出来的“稠密向量（几百维），意思相近的词方向也相近。详见另一张卡片《词向量 / 词嵌入》。

② 分词 ≠ 词形还原（Lemmatization）。分词只是“切开”，“study / studies / studied” 分完还是三个不同的词、三个不同的维度；词形还原会把它们归成一个原形，是切完之后额外做的一步 [来源 6]。

③ 词袋丢掉的不只是语序，还有否定。“效果好”和“效果不好”在词袋里只差一个“不”，权重还常常被 IDF 压得很低——情感分析里这个坑非常常见。

④ TF-IDF 不是”语义相似度“。它算的是”词面重合度“。同义不同词（面试 / 笔试）、一词多义（苹果公司 / 苹果水果）它都处理不了，因为它压根不知道词的意思。

⑤ 维度爆炸与稀疏。10 万词的语料就是 10 万维向量，其中 99% 以上是 0。这也是实际工程里必须用稀疏矩阵（scipy.sparse）存储、并靠 min_df / max_df / max_features 做词表裁剪的原因 [来源 1][来源 2]。

⑥ IDF 依赖语料统计，换语料要重新拟合。IDF 是在”这一批文档“上统计出来的；把模型用到完全不同领域的文本上（比如用新闻语料训练的权重去处理医学论文），权重会失真。语料太小的时候 IDF 本身也不稳定。

⑦ 中文必须先分词，切错了后面全错。“乒乓球拍卖完了”到底是“乒乓球 / 拍卖 / 完了”还是“乒乓球拍 / 卖 / 完了”，分词一旦切错，词表里就是两个完全不同的维度，后面无论多好的模型都救不回来。

  3. Q3 概念辨析：正确答案 D。TF-IDF 向量是稀疏的计数/加权向量，维度等于词表大小；词嵌入才是稠密的、语义相近的词方向相近的向量。

  6. Q6 风险边界：正确答案 D。同义不同词、语序与否定丢失、高维稀疏带来成本，都是词袋 / TF-IDF 的固有局限，需要靠词嵌入或更复杂的模型补足。
