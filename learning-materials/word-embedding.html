词向量 / 词嵌入（Word Embedding · 余弦相似度）

把每个词放到一张高维的“意义地图”上，给它一组坐标数字；意思相近的词，坐标也彼此靠近——这组坐标就叫词向量。

生成日期：2026-09-17 · 学习视角：AI 初学者 · 承接《文本的数字化》卡片 · 资料来源均为公开可核查链接

01学习目标

  • 能说清 词嵌入（Word Embedding）到底解决了“计数向量”的什么毛病，两者的区别在哪。
  • 能用自己的话解释“意思相近的词，向量方向也相近”这句话，以及它背后的分布式假设。
  • 能说明余弦相似度在算什么、为什么它比“向量距离”更适合比较词与词、文档与文档。

02核心问题

  • 如果用“每个词占一个维度”的表示法，“猫”和“狗”之间的距离，和“猫”和“量子力学”之间的距离一样远——这为什么是个大问题？
  • 词向量里的那几百个数字，是人工定义的吗？如果不是，模型靠什么把它们“学”出来？
  • 余弦相似度为什么只看“方向”不看“长短”？这会带来什么好处和什么坑？

03个人解释

我的理解：

学完《文本的数字化》之后我一直有个别扭的感觉：TF-IDF 虽然能用，但它其实完全不认识词的意思。“考研”和“保研”在它眼里是两个毫不相干的方向，只因为字面不重合，就被判成没关系。词嵌入要解决的正是这件事。

我觉得最好懂的比喻是一张“意义地图”。地图上每个地点有经纬度；词嵌入就是给每个词在这张（几百维的）地图上算出一组坐标。“猫”和“狗”是邻居，“汽车”和“轮胎”离得不远，而“猫”和“微积分”隔了很远。这样一来，机器终于能算“两个词有多像”了——直接量它们在地图上的方向和距离就行。

更让我意外的是这组坐标不是人定的。没有人规定第 37 维代表“是否和动物有关”。模型只是被反复要求做一件很朴素的事：看上下文，猜这个词（或者反过来，看这个词，猜它周围会出现什么词）。猜得多了，意思相近的词自然被推到一起——因为它们的“邻居”本来就长得像。这背后是语言学里那句老话：观其伴，知其义[来源 1]。

最后是余弦相似度。我原来以为比较两个向量就是量它们的距离，其实更常用的是量夹角：两把箭头指的方向越接近，越相似。好处是它不管箭头多长——一篇文章写得长、词出现得多，方向却不该因此变掉。这也是为什么它常和 TF-IDF 向量、句向量搭配使用 [来源 5]。

作为大二学生，这节是我第一次真切体会到“模型自己从数据里学出结构”是怎么回事。以前我以为“让机器懂语义”得靠人写规则、编词典；结果 word2vec 的做法朴素到只是“用邻居猜词”，语义却自己浮现出来了。另外我也第一次意识到：词向量学到的是“经常一起出现”，不等于“意思一样”——“热门”和“冷门”经常出现在同一个句子里，向量可能很接近，意思却相反。这一点我以前完全没想过，也是我以后用向量检索时最需要提防的坑。——杨国美

04核心机制 / 组成

① 先看老办法错在哪：One-hot（独热）表示。如果词表有 5 万个词，就给每个词一个 5 万维的向量，只有自己那一维是 1，其他全是 0 [来源 4]。

  • 太占地方：5 万个词就是 5 万维，其中 49999 个都是 0。
  • 彼此“一样远”：任意两个不同词的向量都是垂直的，夹角 90 度——在数学上，所有词两两的“相似度”都是 0。机器因此完全无法表达“猫和狗比较像” [来源 4]。

② 词嵌入的解法：把稀疏的“编号”换成稠密的“坐标”。用一个几百维（常见 100 ~ 1000 维）的稠密向量表示一个词，每一维都是一个有正有负的小数，不再是 0/1 [来源 2][来源 4]。这样近义词的向量方向就会自然靠近，机器终于能算相似度了。

③ 这些坐标是怎么学出来的？——分布式假设 + 猜词游戏。核心思路是：一个词的意思，由它经常一起出现的那些词决定（即“观其伴，知其义”）[来源 1]。具体做法就是让模型反复做“填空”：

  • Word2vec 的 Skip-gram：给模型一个词（如“咖啡”），让它猜周围可能出现的词（“喝 / 早上 / 提神”）。
  • Word2vec 的 CBOW：反过来，给周围的词，让它猜中间缺的那个词。
  • GloVe：不一个个句子地猜，而是先统计整份语料里“谁和谁一起出现过多少次”（共现矩阵），再拟合出一组能解释这些统计量的向量 [来源 2]。

训练完之后，中间那层“每个词对应的那排数字”就是词向量。上面两种路线都发现：学出来的向量能支持像 国王 - 男人 + 女人 ≈ 王后 这样的加减运算，说明方向真的编码了某种“意义差”[来源 1][来源 2]。

④ 四种“文本表示法”放在一起对比（这是最容易搞混的一组概念）：

表示法怎么来的维度 / 稠密度能表达近义词吗
One-hot词表里每个词占一维，自己做 1几万维，极稀疏不能，所有词两两正交
词袋 / TF-IDF统计计数或加权几万维（=词表大小），极稀疏不能，只看字面重不重合
静态词嵌入（word2vec / GloVe）从语料里“学”出来的稠密坐标几百维，稠密能，近义词方向接近
上下文相关嵌入（BERT / GPT 类）把整句话喂进 Transformer，每个位置的向量随上下文变化几百到上千维，稠密能，且能区分同一个词的不同含义

注意最后一行：静态词嵌入里“苹果”只有一个向量，无论你说的是水果还是手机；而 BERT / GPT 这类模型会根据句子现场算出一个专属向量，所以“苹果手机”和“苹果很甜”里的“苹果”是两个不同的向量 [来源 9]。

⑤ 余弦相似度：怎么算“两个向量像不像” [来源 5]。

  • 直觉：把两个向量看成从原点出发的两支箭，量它们之间的夹角。夹角越小越相似。
  • 取值范围：结果被归一化到 −1 到 1 之间——1 表示方向完全一致，0 表示毫无关系（垂直），−1 表示方向完全相反 [来源 7]。
  • 为什么不用直线距离：因为向量的“长度”常受文本长短、词频高低影响。余弦相似度只看方向，把“长度”这个干扰因素消掉，所以特别适合比较长短不一的文档 [来源 5]。

从“词”到“可比较的坐标”

词语 → [在语料里学习：用上下文互相预测] → 每个词一组稠密坐标 → [余弦相似度] → 一个 −1~1 的“像不像”分数

一句话记忆法：词袋是“数出来”的向量（只看字面），词嵌入是“学出来”的向量（带意思）；余弦相似度 = 量夹角，不看长短。

05应用场景（具体例子）

场景：给校园二手书小程序做“语义化搜索”，让用户搜“高数 同济 第七版 教材”时，也能找到标题写着“高等数学 同济大学出版社 上册”的那本。

  • 谁用：我和同组同学做的校园二手书小程序，商品标题由学生随手写，极不规范。
  • 什么环节：用户搜索。原来的方案是关键词匹配（LIKE %高数%），结果“高等数学”完全搜不到，因为两个字面上没有共同子串；用户只能自己换词反复试，转化率很低。
  • 怎么做：① 用 sentence-transformers（基于 Sentence-BERT 的句向量工具）把每条商品标题转成一个几百维的向量，离线预先算好存进数据库 [来源 6]；② 用户输入查询词，也转成同一个模型产出的向量；③ 用余弦相似度和库存里每条商品的向量比一遍，取分数最高的 Top 20 [来源 5]；④ 为了让“第七版”和“第八版”不被混为一谈，在向量召回之后再加一道关键词硬过滤（标题里必须含相同版本号）。
  • 解决了什么：“高数 / 高等数学 / 数学分析”这类同义表述终于能互相搜到——这在纯关键词方案里是做不到的，因为词面根本不重合。同时因为向量可以预计算，线上只需做一次余弦相似度计算，延迟可以接受。
  • 暴露的代价与坑：① 模型下载和推理都有成本，比关键词匹配“重”得多；② 语义相近 ≠ 商品相同，模型会把“第七版”和“第八版”判得很像（它们语境几乎一致），所以必须叠加关键词过滤；③ 通用模型在“二手书”这种垂直小领域未必比 TF-IDF 更准，我们最后用的是向量召回 + 关键词过滤的混合方案，而不是纯向量。

06易混淆 / 使用边界

① 词嵌入 ≠ 词袋 / TF-IDF。词袋是“数出来”的稀疏向量，维度 = 词表大小，只反映字面出现情况；词嵌入是“学出来”的稠密向量，几百维，能反映语义相近程度。两者都能算余弦相似度，但算出来的含义完全不同。

② 静态词嵌入 ≠ 上下文相关嵌入。word2vec / GloVe 给一个词一个固定向量，“苹果”（水果）和“苹果”（公司）是同一个坐标；BERT / GPT 这类模型按上下文现场计算，同一个词在不同句子里向量不同，因此能区分多义 [来源 9]。

③ 余弦相似度不是概率，也不是“正确率”。0.85 只表示方向很接近，不表示“85% 的可能性是对的”。而且这个数值的绝对大小受模型、语料、维度影响，跨模型比较毫无意义——只能在同一模型内部比大小。

④ 向量相近 ≠ 意思相同，更 ≠ 可以互换。这是最反直觉也最危险的一条。词向量学到的是“经常一起出现”的统计规律，所以“热门 / 冷门”“上涨 / 下跌”这类经常出现在同一语境但意思相反的词，向量常常相当接近。相似度只回答“像不像”，不回答“是不是、能不能替换”。

⑤ 单个维度没有可读含义。没人能告诉你第 137 维代表什么。词向量的意义是“整体方向上的相对关系”，不要试图把某一维解读成人能理解的属性（个别维度偶尔能对应上某种语义，属于经验现象，不是设计目标）。

⑥ 有领域漂移问题。通用语料训出来的词向量，用在医学、法律、古汉语等垂直领域，效果可能明显下降，甚至不如老老实实的 TF-IDF。领域越专，越需要考虑用自己的语料微调或重训。

⑦ 只能算“像”，不能推理。词向量与余弦相似度都是相似度工具，不会告诉你因果、不会做逻辑判断。它适合“召回 / 排序 / 聚类”，不适合当“判断真相”的依据。
